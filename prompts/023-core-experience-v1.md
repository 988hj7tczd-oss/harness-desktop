## Part A：聊天体验（最高优先）

### A1. 消息复制
- MessageBubble 每条消息 hover 显示操作按钮（CSS，不用 emoji）：
  - **复制**：复制消息全文到剪贴板（navigator.clipboard）
  - 复制成功给轻提示（按钮文字变"已复制"2 秒，或 toast）
- 用户消息 + assistant 消息都支持
- 代码块：保留现有样式，复制整条消息（含代码块文本）

### A2. 消息编辑（用户消息）
- 用户消息 hover 显示"编辑"按钮：
  - 点击 → 消息变为编辑态（textarea 显示原文）
  - 确认 → **替换该消息 + 重新触发 agent 回复**：
    - 编辑后：更新本地消息文本
    - 调 harness 重新发送（编辑后的消息作为新输入，原回复作废/标记）
    - 实现方式参考 dsh 是否有"重发/编辑"语义；没有则：更新本地显示 + 发新消息，
      原 assistant 回复标记为"已编辑，见新回复"（或隐藏）
- 取消 → 恢复原样

### A3. 重新生成（assistant 消息）
- assistant 消息 hover 显示"重新生成"按钮：
  - 点击 → 重新触发同一用户消息的回复（重跑 turn）
  - 新回复**替换**旧回复（或标记"重新生成中"，完成后替换）
- 实现：harness 重新发送该条消息前的用户输入，或 dsh 的 cancel+retry（查 API）

### A4. 流式优化（已有打字机，再加细节）
- 当前已有：乐观 UI + assistant-delta 逐字 + 思考中动画 + stream-caret
- 增强：
  - 流式中显示**耗时/速度**（可选，低调显示）
  - 流式结束时 caret 消失、消息"落定"（状态 streaming → done）
  - 错误时的流式消息：显示错误 + 保留已生成部分 + 重试按钮
  - token 统计（assistant/message 事件带 usage → 显示"XX tokens"）

### A5. 交互细节
- hover 操作按钮不遮挡文本（绝对定位右上角/右下角，半透明，hover 才显示）
- 按钮图标用 CSS/SVG 内联（不用 emoji、不引图标库）

## Part D：会话轨迹（新增，owner 要求）

### D1. 是什么
展示 agent 在一轮对话中的**完整执行轨迹**——用户看到的不只是回复，
而是 agent "怎么想的、调了哪些工具、分几步、花了多久"的透明过程。

### D2. 数据来源（dsh 事件流，adapter/events.ts 已处理）
| 事件 | 轨迹节点 |
|---|---|
| `user/message` | 用户输入（起点）|
| `turn/start` | 回合开始 |
| `assistant/chunk` (reasoning) | 思考过程节点 |
| `step/start` / `step/end` | 执行步骤（名称/耗时/状态）|
| `tool/call` / `tool/result` | 工具调用（工具名/参数摘要/结果摘要/耗时）|
| `assistant/message` | 最终回复（终点）|
| `turn/end` | 回合结束（结果 completed/error + 总耗时）|

### D3. UI 设计
- **会话轨迹面板**（聊天界面右侧可折叠，或消息下方"查看轨迹"展开）：
  - 时间线视图：按时间顺序显示节点
  - 每节点：图标（CSS/SVG）+ 标签 + 摘要 + 耗时
  - 工具调用节点：工具名 + 参数（可展开看全）+ 结果（成功/失败）
  - 思考节点：可展开看 reasoning 文本
  - 回合总览：总耗时 + 步骤数 + 工具调用数 + token（如有）
- **交互**：
  - 消息下方"查看轨迹"链接（hover 或常显小字）
  - 点击展开轨迹面板（不是新页面，就地展开或右侧抽屉）
  - 轨迹节点可折叠/展开（工具参数/思考详情默认折叠）

### D4. 数据流
- 前端已通过 bus 收到所有事件（subscribeSession）→ 维护 per-session 轨迹数组
- 历史加载（getHistory）时也解析事件 → 重建轨迹
- 轨迹与消息对应：按 turn 分组（turn/start 到 turn/end 算一个轨迹段）
- 不落盘（会话历史已有），只在 UI 展示时组装

### D5. 与现有功能的关系
- 不改变消息列表/流式渲染（轨迹是附加视图）
- 工具调用卡（已有 ToolCallCard）可复用为轨迹里的工具节点
- 任务面板的步骤（TaskStep）与轨迹步骤同源（都来自 step 事件），可共用

# 任务：Agent 进化闭环 —— 让 agent 完成用户任务并越用越强

项目：~/development/harness-desktop
基于：001-004 已验收（壳/UI/模型/凭证/提醒/记忆表/计划/搜索/导出/快捷键/Telegram）

## 产品定位（本次重构的灵魂）
不是"功能堆砌的聊天壳"，而是**任务驱动 + Agent 进化闭环**：

```
任务进来 → agent 完成 → 复盘提炼 → 技能沉淀 → 下次更快更好
     ↑______________________________________|
```

**"训练 agent" = 每一次任务都在让 agent 变强**：
- L1 记忆层：任务后自动复盘，把用户偏好/项目约定/成功做法写入记忆，下次自动注入
- L2 技能层：同类任务做 3 次自动提炼成 SKILL，下次直接调用
- 目标：用户说人话 → agent 高效完成 → 用户感到"它越来越懂我"

## 技术事实（已验证，开发前必读）
1. dsh API 信封：POST /api/<method>，{type:"client-request",rpcId,method,payload} → {type:"server-response",rpcId,result:{ok,value|error}}
2. 会话事件流：WS /api/events.mux 下推帧；turn/*, step/*, user/message, assistant/*, tool/* 事件
3. 现有能力：
   - harness-memory 插件（ctx.storageDomain memories 表 + system-prompt section 注入）
   - dsh schedule 工具（schedule_create/list/delete）
   - dsh skill 系统（ctx.skills + tool-skill + skill-filesystem：扫描 SKILL.md）
   - session.history 拉全量事件；assistant/message 自带 usage
4. 004 已实现：CredentialsSection/RemindersSection/MemorySection/MessageChannelsSection/ConsoleSection（组件都在但布局是长弹窗一屏堆，需要改）
5. 锁 @deepseek-ai/dsh@0.1.0-rc.6 不变，adapter 隔离原则不变

## Part B：任务面板（闭环入口，核心）

### B1. 任务追踪
- 任务卡片列表：任务标题 + 状态（排队/进行中/完成/失败）+ 开始时间 + 耗时
- 任务来源：
  - 用户在聊天区发起（一句话就是一个任务）
  - 定时触发（schedule 到点）
  - 外部通道（Telegram 消息）
- 任务状态从会话事件流推导：turn/start → 进行中，turn/end → 完成/失败

### B2. 任务进展可视化（用户体验关键）
- 进行中的任务显示**步骤进度**（从 tool/* 事件推导：正在收集数据/正在生成/正在润色…）
- 任务卡可点开：看完整执行轨迹（调用哪些工具、结果如何）
- 完成的任务显示结果摘要 + ✅ 标记
- 失败的任务显示错误原因 + "重试"按钮

### B3. 任务完成体验
- 任务完成后自动生成简短摘要（做了什么/结果如何/耗时）
- 可一键"复盘"（Part C）

## Part C：记忆进化（L1 训练，越用越懂用户）

### C1. 自动复盘
- 任务完成后（turn/end 且成功），主进程触发复盘：
  - 提取本次任务中的**用户偏好**（如"用户喜欢简洁回答"）
  - 提取**项目约定**（如"项目用 pnpm"）
  - 提取**成功做法**（如"处理这种任务时先搜索再回答"）
- 写入 harness-memory 的 memories 表（带 tags: preference/project/practice）

### C2. 记忆注入（已有，增强）
- 保留现有 system-prompt section 注入机制
- 增强：注入时按 tags 分类展示，让 agent 明确知道哪些是偏好、哪些是约定

### C3. 记忆管理 UI（004 已有，增强）
- 记忆列表按 tag 分组：用户偏好 / 项目约定 / 成功做法 / 其他
- 每条可：编辑 / 删除 / 标记重要
- 显示记忆来源（从哪个任务/会话提炼的）
- 设置项："自动复盘"开关（默认开）+ "自动注入记忆"开关

## Part D：技能沉淀（L2 训练，同类任务越做越快）

### D1. 技能提炼
- 同一类任务完成 3 次后（按任务类型/标题相似度聚类），自动提示提炼 SKILL
- 提炼内容：任务类型 + 标准步骤（从轨迹提取）+ 常见坑 + 验证方式
- 生成 SKILL.md 存入技能目录（~/development/harness-desktop/skills/ 或用户可配置目录）
- 通过 ctx.skills + skill-filesystem 注册，agent 下次可自动调用

### D2. 技能管理 UI
- 设置页"📚 技能"区：浏览全部 SKILL（名称/描述/使用次数）
- 操作：启用/停用/删除/查看内容
- 显示每个技能的来源任务和沉淀时间

### D3. 技能自动调用
- 新任务进来时，agent 能发现并加载相关 SKILL（dsh tool-skill 已有此能力，确认接通）

## Part F：用户体验优化（贯穿所有部分）

### F1. 反馈即时性
- 发送任务后立即出现任务卡（不是等 agent 想完才显示）
- 流式输出照旧，但任务卡同步显示步骤状态
- 长任务显示"正在…" + 可取消按钮

### F2. 错误友好
- 引擎未就绪/API Key 未配置/网络错误 → 友好提示 + 引导去对应设置
- 失败任务可一键重试（重新发同一 prompt）

### F3. 首次体验
- 首次启动向导（已有）补充：引导创建一个示例任务，让用户看到"任务→完成→复盘"全流程
- 空状态引导：无任务时显示"试试对我说：整理这个项目的 TODO"

### F4. 视觉一致性
- 任务面板/设置导航/卡片全部沿用 --dsw-* token（003 已建立）
- 动画克制：转圈/进度用现有节奏，不花哨

## 验收标准（owner 实测）
1. 设置页是左右导航布局，7 个分区切换正常
2. 主界面有任务入口，切换任务面板
3. 发起一个任务（如"帮我总结这个项目"）→ 任务卡出现 → 进展更新 → 完成后有摘要
4. 任务完成后自动复盘：记忆里出现新条目（带来源），重启后仍在
5. 同一任务做 3 次 → 提示/生成 SKILL，技能区可见
6. 新建每日任务 → 到点自动创建任务并执行
7. 失败任务显示错误 + 重试可用
8. 无任务/无记忆/无技能时都有友好空状态
9. pnpm typecheck 零错误，pnpm dev 正常启动，Telegram 通道不受影响
